Mammoth Academy · Game Layer Blueprint

Nov 3, 2026Status: built Nov 3 (A-F merged, all tests pass), not deployed yetRepo: Mammoth/MammothAcademyStarted from: Gemini's "high-dopamine engine" plan

The one rule behind every choice here: the game has to measure the same thing as the exam. A boss you beat by grinding flashcards feels great and then you still fail SAA-C03. So the boss bar measures how much you'll still remember next week. Combos, sounds and visual effects make that feel good, but they never inflate it.

Three loops do the learning: miss → see the rule → get asked again (in the same session), come back tomorrow → review what's due (across days), and domain bosses → final boss = a full timed exam (readiness). The CSS lab at the bottom has live demos of every visual idea. Try them on your phone.

03Data model (the foundation everything sits on)

All progress lives in each browser's localStorage and moves between devices through sync.js Smart Merge. Every new key needs a merge rule before it ships, or phone and PC drift apart.

Existing bug found while planning: st_failed_qs is in UNION_KEYS (sync.js:21). Clear a question on your phone, merge with the PC, and it comes back, forever. A list that should shrink can't be merged by union. The new review store fixes this by keeping one record per question, and the newest record wins.

Question ids

Use Jake's existing scheme so the two systems can share history later: <courseId>:mc:<sha1(question text) first 10 hex> (build-study-bank.js:18). Browsers can't run SHA-1 without waiting (crypto.subtle is async), so a build step stamps an id onto every question in courses/*.js, with a check that no two collide. Editing a question's text changes its id. That's accepted, and it's how Jake already works.

Review engine (Leitner, same idea as Jake's)

Box0123 = mastered45
Next duethis session (rematch)+1 day+3 days+7 days+16 days+35 days
  • Right answer → up one box, at most one move per calendar day. Getting a question right three times in a row in one sitting doesn't count as spaced.
  • Wrong answer → box 0 (rematch this session), then due tomorrow. m ≥ 2 shows the Nemesis badge until it's answered right on 3 separate days.
  • Days use your local date (the laptop travels; you're in CET). The day rolls over at 04:00, so late-night study counts for the day you're still in.
  • The Arena's "missed first" draw (app.js:446-474) switches from st_failed_qs to "due or box 0 first", which makes it smarter at no extra cost.

Readiness formula (what the boss bars show)

domain mastery  = questions in that domain at box ≥ 3  ÷  all exam questions tagged with that domain
sub-boss HP     = 100% − domain mastery
readiness       = Σ (blueprint weight × domain mastery)        e.g. 0.30·Secure + 0.26·Resilient + 0.24·Perf + 0.20·Cost
final boss      = unlocks when every domain ≥ 80% → a FULL timed Arena exam (65 q, 130 min); beat it at ≥ pass mark

Mastery decays on its own: a question at box 3 that goes overdue by more than its interval counts as only half mastered until it's reviewed again. So a boss you leave alone for two weeks visibly grows back. That's honest feedback, not a punishment for a single miss.

Thin banks: a domain with fewer than 15 questions shows "Not enough questions to measure yet" instead of a fake bar (Cloud+ Security has 0, and A+ domains have 1 to 4). Only AWS gets real bosses today.

04Features

F1 · Active track lock S

One track drives Home, Daily, Gym, Arena defaults and Path. The other six fold into a "Switch track" drawer (<details>, animated with interpolate-size where supported).

Where

index.html track grid (~413), library course switcher, daily.html track buttons, arena exam list, path.html cards. A shared Track.get()/set() helper in a new game.js.

Done when

After a fresh install every page opens on AWS. Switching on the phone, then syncing, switches the PC too. Library deep links to another track still work, so the lock only sets defaults and never blocks you.

F2 · Review engine + migration M

The game.js core: Review.record(qid, right), Review.due(courseId), Review.mastery(courseId), the day log, and the streak derivation. Every answer surface calls record(): Arena (practice instantly, exam mode at submit), lesson quizzes (answerQuiz, app.js:1237), Daily Flash, the homepage card.

Where

New www/game.js loaded on every page before app.js. sync.js gets the three merge rules. A one-time migration from st_failed_qs. Build step: tools/stamp-question-ids.js.

Done when

A unit test drives a fake clock through 40 days and every box and due date matches the table. Merging A into B, then B into A, then repeating gives the same result (idempotent). A migrated device keeps its missed list. Corrupt or missing storage never throws (private windows).

F3 · Intel drawer on a miss M

A wrong answer slides up a bottom sheet (lab #6) showing: the trap (whyWrong[chosen], app.js:426), the rule (the correct option plus exp), and two links: Read the lesson (deep link into Library) and Cram Sheet (opens the right sheet already searched).

Content job

Add an optional ref per question: {"module":"<exact title>","topic":"<exact title>","cram":["aws","Glacier"]}. agy authors it for the 213 AWS questions, and a validator script fails the build if any title doesn't resolve. Without a ref, the domain → module map (meta.domains) is the fallback. Cram.open(sheetId) (cram.js:268) gets a second argument, query.

Where it shows

Arena practice mode, lesson quizzes, Daily, the homepage card. Never in exam mode: testing-center fidelity stays, and the results autopsy gets the same links per wrong question.

Done when

Every AWS question resolves to a real lesson and topic. The drawer is keyboard-closable (Esc), focus returns to the next question, it works at 390 px wide, and it works in Mammoth mode.

F4 · Rematch S

A missed question comes back 3 cards later with its options shuffled, plus a "⚔ Rematch" tag and a small "Revenge" effect when you clear it. In exam mode there's no rematch (fidelity).

v2, optional: agy writes one variant per AWS question (same concept, new scenario), reviewed like the Oct 18 content. Then the rematch tests the concept, not your memory of the wording.

Done when

Miss Q at position 4 and it reappears at 7 with a different option order. Near the end of a set it goes last. Clearing it marks the review record but doesn't promote it past box 1 that day.

F5 · Homepage "next question" card S

Returning visitors get one live question at the top of index.html: the most overdue review for the active track, otherwise an unseen question from the weakest domain. No timer. Answering opens the drawer on a miss and loads the next card with a view transition (lab #10). A "5 more" button chains a quick set.

Where

index.html above the stats (~386). The hero copy (~357) collapses into a one-line strip for returning users (D3). Note: app.init() must not run on index.html (MEMORY.MD), so the card uses game.js plus course-loader only.

Done when

Cold load to an answerable card in under 1 s on the phone, offline included. New visitors still see the pitch.

F6 · Daily minimum + streak S

The streak counts days with ≥5 answers anywhere (D1), derived from st_daylog. Hitting the minimum gives a one-time celebration plus the "overclock" theme for the rest of the day (lab #9), purely cosmetic. The flame heats up with the streak length (lab #7).

Where

Replace the streak writes in daily.html:559-569 and 715-724 with Review calls. Home stat (index.html:528) reads the derived value. The Achievements streak badges keep working unchanged.

Done when

Clock tests: 5 answers at 23:50 plus 5 at 00:10 = 2 days. A missed day resets. Two devices that each studied on different days merge into the longer streak. Travel across time zones doesn't double-count.

F7 · Domain bosses on Smart Path M

The active track's card on path.html becomes a boss panel: one ring per blueprint domain (lab #2), a combined readiness bar with chip damage (lab #1), and the final boss locked until every domain is ≥80%. A domain dropping to 0 HP fires the burst (lab #8). The existing completion bars (path.html:321-363) move into a "Coverage" fold, since coverage still matters but it isn't readiness.

Done when

Bars match the formula in section 03 for a seeded state. Thin-bank tracks show the "not enough questions" state. The final boss result writes the normal Arena high score.

F8 · Juice layer S

www/juice.css + www/juice.js, exporting juice(event, el): adds a class, removes it on animationend, optionally plays a synth tone (Web Audio, no files, so it stays offline) and vibrates on Android (navigator.vibrate, a no-op on iOS). Every effect has a reduced-motion version (colour, no movement) and pulls colours from the theme tokens, so Mammoth mode re-skins it for free.

05CSS lab: try each trick

Everything below is plain CSS with a few lines of JS to trigger it. No libraries, all offline-safe. Tick the box to preview the reduced-motion version. Newest features (trig functions, @starting-style, view transitions, scroll timelines) work in current Chrome, Safari and Firefox and quietly do nothing in older ones.

1 · Boss bar with chip damage + rolling numbers @property

Fighting-game trick: the red bar drops instantly and a pale "chip" bar follows 0.45 s later, so you see how much damage you did. The number rolls because --num is registered as an <integer>, which lets CSS animate it.

SAA-C03 · Readiness boss% HP
@property --num { syntax:'<integer>'; inherits:false; initial-value:0 }
.count { counter-reset:n var(--num); transition:--num .6s }
.count::after { content:counter(n) }
.hp .fill  { width:calc(var(--hp)*1%); transition:width .12s }
.hp .ghost { width:calc(var(--hp)*1%); transition:width .55s .45s }  /* the chip */

2 · Sub-boss rings (one per exam domain) conic-gradient + mask

One element, no SVG: a conic gradient sweeps to --pct, and a radial mask punches out the middle. Registering --pct lets the sweep animate smoothly. Turns green with a check at 80%.

.ring { background:conic-gradient(var(--accent) calc(var(--pct)*1%), #18213a 0);
        mask:radial-gradient(farthest-side, #0000 70%, #000 71%);
        transition:--pct .9s }

3 · Question card: press, shake, pulse, drawer :has() @starting-style

Press = scale:.98 on :active. A miss shakes the card using the separate translate property, so it never fights the press scale. The card border reacts through .qcard:has(.opt.wrong), with no JS class juggling. The drawer is a native <dialog>: @starting-style + transition-behavior:allow-discrete animate it in and out with zero animation JS, and you get Esc-to-close and focus handling for free.

A company needs S3 objects retrievable within 12 hours at the lowest cost, accessed about once a year. Which storage class?

4 · Streak flame that heats up color-mix()

One --streak number drives the colour (amber → red via color-mix(in oklch, …)) and the glow radius. The flicker uses scale/rotate from the base of the flame. Drag the slider.

3day streak 
.flame { color:color-mix(in oklch, #fbbf24, #ef4444 calc(var(--streak) * 7%));
         filter:drop-shadow(0 0 calc(var(--streak) * 1.2px) currentColor) }

5 · Sub-boss down: radial burst sin() / cos()

Twelve sparks, each with --i. CSS trig functions place them on an ellipse, so there's no canvas and no particle library. Good for PBQ clears and dead sub-bosses (the homepage already has a #particle-canvas, but this is lighter).

DOMAIN DOWN
.burst-box span { --a:calc(var(--i) * 30deg); animation:burst .75s forwards }
@keyframes burst { to { translate:calc(-50% + cos(var(--a))*64px) calc(-50% + sin(var(--a))*46px); opacity:0 } }

6 · "Overclock": daily minimum hit inherited @property

Gemini's neon idea without the double damage. A registered, inherited --hue animates and every child colour built from oklch(… var(--hue)) follows, so the whole theme glides from cyan to magenta. In the app this would be body[data-daily="done"].

Daily minimum 2 / 5 answers
@property --hue { syntax:'<number>'; inherits:true; initial-value:200 }
.oc { --acc:oklch(.87 .16 var(--hue)); transition:--hue 1.2s }
.oc.on { --hue:330 }

7 · Next card with a view transition View Transitions API

document.startViewTransition(update) snapshots the old card, swaps the content, and animates between them using pseudo-elements you style in CSS. For moving between pages (Home → Arena) the app can add one line, @view-transition { navigation: auto; }, and page loads cross-fade too. Needs a test with the service worker.

CARD 1 / 5
.vt { view-transition-name:qcard }
::view-transition-old(qcard) { animation:vtOut .22s }   ::view-transition-new(qcard) { animation:vtIn .28s }

Small useful ones (no demo needed)

  • Scroll-driven progress bar (look at the top of this page): animation-timeline: scroll(root). Use it for lesson reading progress in the Library. No scroll listeners.
  • font-variant-numeric: tabular-nums on the Arena timer, HP numbers and stats, so digits stop jittering as they change.
  • scrollbar-gutter: stable: the page doesn't jump sideways when a drawer locks scrolling.
  • body:has(dialog[open]) { overflow:hidden }: scroll lock with no JS.
  • @media (hover:hover) around hover styles, so phones don't get stuck hover states after a tap.
  • text-wrap: balance on headings and pretty on lesson prose: no more one-word last lines.
  • Container queries (container-type:inline-size): one question card that adapts to its slot (homepage, drawer, Arena), not to the screen.
  • interpolate-size: allow-keywords + ::details-content: the "Switch track" drawer animates to height:auto (Chrome now, others ignore it safely).
  • accent-color: themed checkboxes and sliders in one line (this page uses it).
